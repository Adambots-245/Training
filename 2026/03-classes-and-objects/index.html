1960sOslo, Norway

      
Two Norwegians who wanted to simulate the world

    

    

      
The goalAt the Norwegian Computing Center, Ole-Johan Dahl and Kristen Nygaard wanted to simulate real systems: factories, traffic, customers waiting in line.

Simula was built for simulation: if you want to simulate 200 customers in a store, you don't write 200 sets of variables. You describe a Customer once and make 200 of them. Same problem as our four swerve modules.

Constructor

    
A constructor sets up each new object

    

      

        
Battery.javawith a constructor


public class Battery {
    String name;
    int year;
    double voltage;

    public Battery(String name, int year, double voltage) {
        this.name = name;
        this.year = year;
        this.voltage = voltage;
    }
    // ...isMatchReady() as before
}


      

      

        
NAMESame name as the class: Battery.

        
NO TYPENo return type, not even void. That's how Java knows it's a constructor.

        
JOBCopy the values handed in into this object's fields.

        
WHENRuns once, automatically, every time you say new.

        
  now in Main.java
Battery a = new Battery("2025-A", 2025, 12.8);

      

    

  

  
Four lines of setup become one, and it's impossible to forget the voltage: the compiler won't let you build a Battery without all three values. Common mistake: writing "public void Battery(...)". With void it silently becomes an ordinary method that never runs on new.

★ Story time

      
1965London, England

      
The billion-dollar mistake

    

    

      
1965British computer scientist Tony Hoare added the null reference to a language called ALGOL W, "simply because it was so easy to implement."

      
DecadesAlmost every language copied it, Java included. Arrows to nothing caused countless crashes, bugs and security holes.

      
2009At a conference he publicly apologized, calling it his "billion-dollar mistake."

      
BonusHe also invented Quicksort, one of the most-used ways to sort data in the world.

      
Even legends make mistakes. The good ones admit it.

    

  

  
Hoare later received the Turing Award (1980) and was knighted. The 2009 talk was at the QCon conference in London. Many newer languages (Kotlin, Swift, Rust) were designed specifically to make null crashes harder.

A mystery from last session, solved

    
Why is main static?

    

      


!!public static void main(String[] args) {


        
When the program starts, no objects exist yet.

        
So main has to work without an object. It belongs to the class: static.

      

      

        
Static methods you've already used

        
Math.max(3, 7) → 7

        
Math.abs(-0.4) → 0.4

        
No new Math() needed. You call them on the class name, because they don't need any object's data.

      

    

  

  
Static methods are fine for things that need no object data: math helpers, main. The trouble starts when code inside main tries to use something that belongs to an object. Next slide.






  

    
The error everyone hits

    
"cannot be referenced from a static context"

    

      


public static void main(String[] args) {
    ⟦describe()⟧;
}


        
  problems
error: non-static method describe() cannot be
referenced from a static context

        
public static void main(String[] args) {
    Battery a = new Battery("2025-A", 2025, 12.8);
    a.describe();
}


      

      

        
TRANSLATION"describe() needs a battery. Which battery? You didn't make one."

        
FIXMake an object with new, then call the method on it.

      

    

  

  
describe() prints "this battery's" name and voltage. Called from main, there is no "this battery", so Java refuses. The fix is always the same: build an object, call the method through it.






  

    
Interactive · the tempting wrong fix

    
Don't "fix" it by making everything static

}

With angle as an instance field, click FL and only FL turns. Flip the switch to static and click again: every module turns together, because there's only one angle for the whole class. It compiles, it "fixes" the error, and it would drive the robot into a wall. Rule: when you get the static-context error, make an object instead.






  

    
Where static is exactly right

    
Constants: static final

    

      


private static final int kMotorChannel = 0;

kWPILib style: constants start with k.

        

      

    

  

  
Values that never change and are the same for everyone are perfect for static final. "final" on its own (without static) also appears in Intake.java on the motor and beamBreak fields: it means "this field always points at the same motor object", set once and never reassigned. Two more mysteries solved.

The front door

    
public methods are the safe way in

    

      


public class SafeMotor {
    private double speed;

    public void setSpeed(double speed) {
        this.speed = Math.clamp(speed, -1.0, 1.0);
    }

    public double getSpeed() {
        return speed;
    }
}


      

      

        
HIDDENThe field is private. Nobody outside can touch it.

        
SETTERThe only way to change it. It can clamp, check, or refuse.

        
GETTERLets others read the value without changing it.

        
Hide the inside. Offer safe buttons on the outside. This is called encapsulation.

      

    

  

  
Like a vending machine: you can't reach in and grab a snack, you press buttons, and the machine decides what happens. Math.clamp(speed, -1.0, 1.0) reads like a sentence: "keep speed between -1.0 and 1.0." Anything above 1.0 becomes 1.0, anything below -1.0 becomes -1.0. It's built into Java (WPILib 2027 uses Java's version instead of its own old MathUtil.clamp).






  

    

      
The robot rule of thumb

      
Fields private, useful methods public

      
    
        
  • Every field in Intake is private
    • 
        
  • run(), stop(), hasGamePiece() are public: other code needs them
    • 
        
  • A helper only this class uses? Make it private too.
    • 
      

      

    

    

  

  
So nothing outside Intake can set the motor directly: it has to ask the Intake to run or stop. If the intake misbehaves, there's exactly one file to look in. Five mysteries solved.

package

    
A package is a folder

    

      package frc.robot.subsystems;
    

    

      
📁frc

Each dot is a folder. The package line must match where the file lives, or it won't compile.

  

  
Packages keep big projects organized and stop name clashes: WPILib's classes live in org.wpilib..., ours live in frc.robot... Two classes can share a name if they're in different packages. If you drag a file into a different folder, VS Code offers to fix the package line for you.

One loop talks to every object

    

      


for (SwerveModule m : modules) {
    m.stop();
}


        
Read it as: "for each module m in modules, stop it."

        
★ The four-module problem, fully solvedOne class, one array, one loop. Fix a bug once and all four modules get the fix.

Each time around, m points at the next module in the array. Compare with slide 4's sixteen variables and four copies of every method. The classic for loop (for int i = 0; i < modules.length; i++) works too; the for-each version is shorter when you just want every item.






  

    
ArrayList

    
ArrayList: a list that grows

    

      


import java.util.ArrayList;

ArrayList<Battery> cart = new ArrayList<>();
cart.add(new Battery("2025-A", 2025, 12.8));
cart.add(new Battery("2024-B", 2024, 12.3));

System.out.println(cart.size());      // 2
System.out.println(cart.get(0).name); // 2025-A


      

      

        
<Battery>"A list of Batteries only." Anything else won't compile.

        
ADDGrows as you add. Arrays are a fixed size; lists aren't.

⚠ Off by one, againcart.get(cart.size()) crashes. The last one is size() - 1.

      

    

  

  
Use an array when the number never changes (four swerve modules). Use an ArrayList when it does (batteries on the cart, game pieces seen by the camera). The for-each loop works on both. Note the import: ArrayList lives in Java's java.util package.

★ Story time

      
1970sXerox PARC, California

      
A computer language for kids

    

    

      
The nameAlan Kay coined the term "object-oriented programming." He pictured objects like living cells: each does its own job and sends messages to the others.

      
SmalltalkHis team built Smalltalk, a language he hoped kids could use to build their own programs.

      
DynabookHe also sketched the Dynabook: a thin, portable computer for children. That was 1972, decades before tablets existed.

      
The ideas you're learning today were designed with students in mind.

    

  

  
Kay later won the Turing Award (2003). Calling a method on an object, like motor.setThrottle(0.5), is what he meant by "sending a message": you ask the object, and it decides how to do it.

Recap

    
Five things to remember

    

      
01
A class is a blueprint. new builds an object.

      
02
Constructors set up new objects. Use this.

      
03
Object variables hold arrows. null means no object.

      
04
static belongs to the class. Never use it to silence errors.

      
05
Fields private, useful methods public.

1 · What does new do?
The class is the blueprint; new builds one real object from it

      
2 · b = a; b.voltage = 11.9; Now a.voltage is...
a and b are two arrows to the same battery

      
3 · Why is main static?
main runs before any object is built, so it belongs to the class

It copies the parameter into itself. Use this.voltage = voltage;
