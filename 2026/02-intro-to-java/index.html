Each computer has its own JVM that translates bytecode for its CPU. It even speeds up as it runs, by compiling the busiest parts on the fly.

"Write once, run anywhere" from last session. The just-in-time (JIT) detail is a one-liner: the JVM watches which code runs most and turns it into fast machine code while the program runs.

Callback to last session's "Power on to program" slide: the JVM is just another program. The OS (Linux on SystemCore) loads the JVM from storage into RAM like any other program; then the JVM loads your .class files and runs them. Two layers of loading: OS loads JVM, JVM loads your code.

The if-semicolon bug is evil because it compiles. Draw it as a box: the if's box is empty (just the semicolon), and the braces after it are a separate box that always runs.

The most important symbol

In Java, = means "store," not "equals"

int x = 5;
x = x + 1;
In math classx = x + 1 is impossible.
1Read the right side first: x is 5, so x + 1 is 6.
2Store the result in the box on the left: x is now 6.
Read = out loud as "gets": "x gets x plus one."

Right side first, then store to the left. Shortcuts for this (x += 1 and x++) come in the operators section. Checking whether two things are equal uses == (coming up in operators).

Five types cover nearly all beginner robot code. long and float are siblings: same kind of value, different box size. long is 64 bits (up to about 9.2 quintillion); you'll see it for timestamps in microseconds. float is 32 bits with about 7 digits of accuracy; WPILib uses double almost everywhere. Why types? Bits again

A type tells the computer how many switches to use

boolean

Just true or false. Basically one switch.

int · 32 bits

Biggest value: 2,147,483,647. Remember Gangnam Style from last session? Need more? long uses 64 bits.

double · 64 bits

Decimals with about 15 to 16 digits of accuracy. Big range, but not perfect: 0.1 + 0.2 is 0.30000000000000004. float uses 32 bits and keeps only about 7 digits.

The type decides how much memory the box gets and what you're allowed to do with it.

Callback to bits and bytes. The 0.1 + 0.2 result is a real Java output; it's why we never test decimals with == on the robot (use a tolerance instead).

Shortcuts

Counting up and down: ++ and --

x = x + 1;

The long way you already know: "x gets x plus one."

x += 1;

Same thing, shorter. Works with any amount: speed += 0.1;

x++;

Shortest: add exactly one. Say it "x plus plus."

x--;

The opposite: subtract one. Say it "x minus minus."

int x = 5;
x = x + 1;   // x is 6
x += 1;      // x is 7
x++;         // x is 8
x--;         // x is 7
★ You'll see these everywhereEvery for loop counts with i++ (next section), and counting down uses i--.You may also see ++x. On its own line, it does exactly the same thing.
  • All three of the first cards do exactly the same thing. Programmers use x++ because adding one is so common (counting laps, game pieces, loop turns).
  • Have the class call out x's value before revealing the trace. Answer: 6, 7, 8, back to 7.
  • Only cover x++ and x-- as statements on their own line. Using them inside bigger expressions is confusing and our code style avoids it.
  • If someone asks about ++x vs x++: on its own line they are identical. They only differ inside a bigger expression. With x = 5, y = x++; gives y = 5 (use, then add), while y = ++x; gives y = 6 (add, then use). x ends up 6 either way. That surprise is exactly why we keep ++ on its own line.

Spot these in your own code

Four classic if mistakes

1 · = instead of ==

if (mode ⟦=⟧ 2) { ... }

Use == to compare.

2 · ; after the condition

if (x > 5)⟦;⟧ { stop(); }

stop() always runs.

3 · Missing braces

if (ready)
    intake.run();
    shooter.fire();   // always runs!

Without braces, only the first line belongs to the if. Always use braces.

4 · Comparing Strings with ==

if (mode ⟦==⟧ "auto")      // ✗ unreliable
if (mode.equals("auto"))  // ✓

Strings use .equals().

Mistake 3 is why WPILib style always uses braces, even for one line. Mistake 4: == on Strings checks whether they're the same object in memory, not the same text. It sometimes "works," which is worse.

The music player that froze

MorningThousands of Microsoft Zune 30 music players froze at the same moment, all over the world.

The most important robot lesson today

Never make robot code wait in a loop

robot loops0every 20 ms
public void periodic() {   // called every 20 ms
    // ✗ waits here, nothing else runs:
    while (!intake.hasGamePiece()) { }
    // ✓ check once per loop instead:
    if (intake.hasGamePiece()) { intake.stop(); }
}
Running: driving, sensors and dashboard all update.
  • Robot code is already inside a loop (every 20 ms). A while loop that waits for a sensor stops that loop: no driving, no other mechanisms, no dashboard. On a real robot the safety system disables the robot when the code stops responding.
  • Click "Try the while loop": the counter freezes. Click "Game piece arrives" to release it. Then "Use the if" to go back to normal.
  • The fix: do one small step per loop (check the sensor once, act, move on). Commands (coming in a later session) make this easy.

★ Story time
1969Apollo 11

Margaret Hamilton's software

1960sMargaret Hamilton led the MIT team writing the onboard flight software for Apollo, and helped popularize the term "software engineering."
LandingMinutes before Apollo 11 touched down, the computer got overloaded and flashed alarms.
SavedThe software was organized into separate jobs with priorities. It dropped the unimportant work, kept the landing jobs running, and the landing went ahead.
Big programs work when they're split into well-organized, named pieces.
  • The famous alarms were "1201" and "1202." Mission control said "go" because they trusted how the software was built.
  • There's a famous photo of Hamilton standing next to a printed stack of the Apollo code as tall as she is.
  • Methods are the first tool for organizing code into named pieces.
Methods

A method is a named recipe you can use again and again

✗ Copy and paste

leftMotor.setThrottle(0);
rightMotor.setThrottle(0);
intake.stop();
// ...and the same 3 lines
// in 6 other places

✓ Write it once

void stopEverything() {
    leftMotor.setThrottle(0);
    rightMotor.setThrottle(0);
    intake.stop();
}
stopEverything();   // use anywhere
★ You've already used methodsSystem.out.println("Hi") and motor.setThrottle(0.5) are method calls. Someone else wrote those recipes.

Fix a bug in one place instead of seven. Give the recipe a good name and the code explains itself.

Anatomy

The parts of a method

double average(double a, double b) {
    double total = a + b;
    return total / 2;
}
doubleReturn type: what kind of value comes back. void means nothing comes back.
averageName: a verb, in camelCase.
( )Parameters: the inputs, each with a type and a name.
{ }Body: the steps of the recipe.
returnHands the answer back to whoever called it.

Read the header out loud: "average takes two doubles, a and b, and gives back a double." In robot code you'll also see public in front: who's allowed to call it (next session).

The method machine · pick one, type inputs, press Run

Inputs go in, a result comes out

⚙️

returns

?
  • average and clamp return a double, isFast returns a boolean, stop() is void: it does something (stops the motor) but hands nothing back.
  • Try clamp(1.4, 1.0): the result is 1.0. Clamping keeps motor outputs in range.
Calling a method

Arguments go in, the return value comes back

double average(double a, double b) { ... }   // definition

double avg = average(2.0, 4.0);               // call
2.0 → aArguments are copied into the parameters, in order.
4.0 → bSame count, same types, same order.
3.0 → avgThe returned value is stored in avg.
◆ WordsParameters are the named slots in the definition. Arguments are the actual values you pass in.

Common errors: wrong number of arguments, wrong types (passing a String to a double), or calling a method and ignoring its return value.

Scope

A variable lives only inside its braces

void teleop() {
    if (buttonPressed) {
        double speed = 0.8;    // born here
        motor.setThrottle(speed);
    }                          // gone here
    System.out.println(⟦speed⟧);  // ✗
}

error: cannot find symbol
  symbol: variable speed
WHYspeed was made inside the if box. When the box closes, the variable disappears.
FIXDeclare it in the outer box, before the if, so both places can see it.

Callback to braces-as-boxes: you can see out of your box, but nobody can see into it. "Cannot find symbol" means either a typo or a scope problem.

Methods on our robot

Name methods like actions and questions

Actions (void)

void drive(double speed)
void stop()
void runIntake()

Do something. Names are verbs.

Questions and readings (return a value)

boolean hasGamePiece()
boolean isAtTarget()
double getAngle()

Answer something. Booleans read like yes/no questions.

Read it out loud: if (intake.hasGamePiece()) { shooter.fire(); }

Good method names make robot code read like a sentence. That's why WPILib and team code use names like hasGamePiece and isAtTarget.
